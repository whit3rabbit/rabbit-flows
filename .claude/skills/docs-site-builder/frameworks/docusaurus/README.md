# Docusaurus

React-based static-site generator for documentation (v3.x). MDX content, classic preset
includes docs + blog + pages + theme.

## Workflow

Work in this order; read the reference when you reach that step.

1. **Scaffold** — new project, file tree, dev commands. → `references/setup.md`
2. **Configure** — `docusaurus.config.js`: title, presets, navbar, footer, sidebar.
   Sidebar (`sidebars.js`) is the fiddly part. → `references/configuration.md`
3. **Author pages** — per-page frontmatter (title, description, slug, sidebar_position,
   tags, displayed_sidebar). → `references/frontmatter.md`
4. **Rich content** — admonitions (`:::note`), code blocks with Prism, tabs, MDX imports,
   math (KaTeX), Mermaid, asset references, partials. → `references/content-authoring.md`
5. **Components** — built-in `@theme/` components (Tabs, CodeBlock, Admonition, DocCardList,
   Mermaid) and custom React components via `@site/src/components/`. → `references/components.md`

For a single narrow question (e.g. "what are the sidebar item types?") read just the one
relevant reference.

## Quick facts

- New project: `npx create-docusaurus@latest my-site classic` (add `--typescript` for TS)
- Config file: `docusaurus.config.js` (or `.ts`) at project root
- Content: `docs/` for documentation, `blog/` for posts, `src/pages/` for standalone pages
- Dev: `npm start` | Build: `npm run build`
- Sidebar: `sidebars.js` — autogenerated via `{ type: 'autogenerated', dirName: 'api' }` or
  explicit category trees; category shorthand via `_category_.json` in a docs subdirectory
- Components import (MDX only): `import Tabs from '@theme/Tabs'; import TabItem from '@theme/TabItem';`
- Admonitions in plain Markdown: `:::note`, `:::tip[Custom title]`, `:::info`, `:::warning`, `:::danger`
- Code blocks: Prism; title via ` ```js title="file.js" `, line highlight `{1,3-5}`, `showLineNumbers`
- Validate: `npm run build` catches broken links (set `onBrokenLinks: 'throw'` in config)

## Authoring guidance

- `.md` for plain prose, `.mdx` when you need React components or JSX. Don't convert to `.mdx`
  unless the file actually uses components.
- Use `autogenerated` sidebar for whole directories; reach for explicit entries only when you need
  custom ordering, labels, or badges.
- Verify prop names against `references/components.md`, not memory — `Tabs` `groupId`, `TabItem`
  `default`, etc. are exact there.
- After config changes, `npm run build` is the check that matters.
